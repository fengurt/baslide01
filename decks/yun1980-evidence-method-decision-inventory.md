| 图形 | 适合回答 | 本项目变量 | 决策 |

### 图形使用底线

- 饼图只用于单层、≤5 类；否则用排序条形。
- 雷达图不用于精确比较。
- 双轴图只在量纲关系不可替代时使用。
- 所有预测 / 条件测算必须带假设、区间或敏感性，不只给单点数字。
- 表格保留用于查数；图形用于判断。不要让同一页同时承担两者。

## 5. Decision quality：每个决策必须带的证据等级

| 等级 | 含义 | 可采取动作 |
|---|---|---|
| A｜直接实测 | POS / 订单 / 菜品明细直接支持 | 可立即执行与设 KPI |
| B｜交叉验证 | 两种算法、两店或多数据源一致 | 可试点后扩展 |
| C｜代理推断 | 缺关键字段，以替代指标估计 | 只做小范围试验 |
| D｜定性判断 | 竞品、访谈、创意推演 | 不承诺财务结果 |
| E｜不可判断 | 缺成本、身份、地址或结算数据 | 先补数，不下结论 |

任何决策卡至少包含：

```text
Decision / Owner / Baseline / Evidence period / Sample size
Method / Assumptions / Confidence / Expected impact range
Pilot / Guardrail / Stop rule / Review date
```

## 6. What else：方法与数据之外还必须有的 10 层

1. **数据血缘**：字段来自哪里、清洗了什么、时间口径是什么。
2. **证据边界**：能证明什么、不能证明什么。
3. **假设台账**：每个测算的关键假设、激进程度与负责人。
4. **不确定性**：区间、敏感性、最坏 / 基准 / 最好情景。
5. **替代解释**：尤其是 DiD 与前后对照，列出混杂因素。
6. **决策权**：谁拍板、谁执行、谁复核，不只写“建议”。
7. **试点设计**：先在哪家店、哪些桌、多久、多少样本。
8. **护栏指标**：收入上升时，毛利、评分、退菜、客诉不能恶化。
9. **停止规则**：什么结果表示方案无效或伤害顾客，应立即停止。
10. **复盘机制**：周看执行、月看结果、季看结构，保留版本与变更记录。

再加两层，报告才会从“咨询分析”变成“经营系统”：

- **品牌 / 顾客证据**：评论文本、访谈、盲测、NPS，防止只优化 POS 数字。
- **利润证据**：BOM、平台结算、人工与租金，防止把收入增量误当利润增量。
